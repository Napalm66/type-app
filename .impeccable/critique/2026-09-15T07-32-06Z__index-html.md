## Design Specificity Verdict

LLM assessment (A): High specificity. Serif-shape spectrum (hand-traced SVGs), font-accurate anatomy diagrams, Key-tell box, Compare's draggable specimen-overlay diff slider are meaningless outside type classification. Font choices historically justified in code comments.

Deterministic scan (B): 16 static findings (15 index.html, 1 js/compare.js). Live overlay found 45-50 anti-patterns per view including ai-color-palette/cream-palette/shape-assembled-illustration - likely false positives given DESIGN.md documents these as deliberate, heavily-iterated choices. em-dash-overuse (12) likely stylistic, consistent house voice. Visual overlays: injection succeeded, real on-page overlay confirmed via screenshots on Explore, Identify-feedback, and detail-modal views.

## Overall Impression

Well-crafted, genuinely bespoke reference tool let down by two things: Timeline quietly fails its own stated purpose for keyboard/screen-reader and touch users, and the quiz's Key-tell callout has an unannounced content gap for 3 of 13 rounds. Neither is a taste problem - both are places the app tells the user one thing and does another.

## What's Working

1. Serif-shape spectrum + anatomy diagram + Key-tell box in the detail modal - genuinely teaches diagnostic recognition, working hover/tap-to-zoom lens.
2. Compare's specimen-overlay diff slider - bespoke, on-brand interaction, not a generic photo-editing before/after.
3. Correct/incorrect feedback asymmetry in Identify - filled accent checkmark + boxed callout for right, plain unpunishing text for wrong. Deliberate emotional design.

## Priority Issues

[P0] Timeline is completely inaccessible to keyboard and screen-reader users
Why it matters: entire lineage tree is one svg role="img" with a single static alt text; none of 13 nodes are focusable or have accessible names.
Fix: tabindex=0 role=button with accessible name, keydown handler, expose tooltip content via aria-describedby.
Suggested command: /impeccable adapt

[P0/P1] Timeline breaks its own promise on touch - the app's stated first-class platform
Why it matters: intro copy says "click for full detail" but touch only toggles a tooltip, no path to the modal.
Fix: add "View full detail" affordance in the touch tooltip, or second-tap opens modal.
Suggested command: /impeccable adapt

[P1] The detail modal claims aria-modal="true" but has no real modal behavior
Why it matters: opening never moves focus in, closing never returns it, no focus trap - Tab continues into the visually-obscured page behind it.
Fix: move focus to close button/panel on open, trap Tab/Shift+Tab, restore focus on close.
Suggested command: /impeccable harden

[P1] The Key-tell callout silently degrades for 3 of 13 classifications
Why it matters: Blackletter, Script, Display have no diagnostics object, so feedback falls back to unlabeled plain sentence with no box - ~23% of rounds quietly deliver less.
Fix: back-fill a real diagnostics.tell for all 13 entries.
Suggested command: /impeccable clarify

[P2] ~26-31 instances of functional text under an 11px legibility floor, plus 12 instances of gray-on-teal text
Why it matters: index numbers, era dates, diagnostic labels, branch tags below common accessibility-floor guidance - systemic, corroborates A's "tight contrast" read with hard counts.
Fix: audit monoXs/monoSm steps (0.62-0.68rem) and gray-on-teal pairs against WCAG AA.
Suggested command: /impeccable audit

[P2] A live quiz reference photo has photo-editing app UI chrome baked into it
Why it matters: images/examples/humanist-1.jpeg shows a visible "Edit" pill and share icon - a raw screenshot artifact, undercuts credibility where accuracy matters most.
Fix: re-crop/re-export without the app chrome.
Suggested command: /impeccable polish

## Persona Red Flags

## Minor Observations

- Compare's picker lists all 13 chips flat for a 2-item pick; Explore's filter row shows 7 ungrouped chips - both push past >=4-visible-options guideline.
- Dense detail modal is one long uninterrupted scroll with no section anchors or progressive disclosure.
- .detail-close, .quiz-restart, .quiz-view-full-inline lack explicit :focus-visible rules - everything else in the system has one.
- Results screen only distinguishes "Perfect score!" from flat "Quiz complete" for everything else - 1/13 and 12/13 read identically.
- js/compare.js:182 uses undocumented rgba(0,0,0,0.75) outside DESIGN.md's palette.
- Footer's "All rights reserved" sits oddly beside the open-font (OFL) credit block directly above it.

## Questions to Consider

2. What if every classification carried a real Key tell so the quiz's reward moment never silently downgrades?
3. What if the results screen's message scaled with score band instead of one generic string?
